# Grafana Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Azure Managed Grafana (Standard SKU) to the guardianlink-dev stack with a crash-pipeline dashboard, fully automated across both local and ADO pipeline execution paths.

**Architecture:** A new `grafana.tf` provisions the Azure resource and role assignments; a new `grafana-dashboards.tf` uses the `grafana/grafana` provider to declare the Azure Monitor data source and crash-pipeline dashboard as code. Local execution uses a two-stage `run.sh apply`; ADO uses `-exclude` on the plan artifact and a separate bootstrap task for provider-side resources.

**Tech Stack:** Terraform 1.9.8, azurerm ~> 4.69, grafana/grafana ~> 3.0, Azure Managed Grafana Standard SKU (Grafana 11), Azure Monitor data source (MSI auth).

**Spec:** `docs/superpowers/specs/2026-04-30-grafana-design.md`

## Task 6: Update `run.sh` — two-stage local apply

**Files:**
- Modify: `terraform/guardianlink-dev/run.sh`

The current `run.sh` ends with `terraform "$@"`. Replace that final line with logic that intercepts `apply` and runs the two-stage bootstrap; all other subcommands pass through unchanged.

- [ ] **Step 1: Replace the final `terraform "$@"` line in `run.sh`**

The full updated file (replace existing content entirely):

```bash
#!/usr/bin/env bash
# Wrapper around `terraform` that injects the external state-backend config
# and the parent subscription ID. Usage: ./run.sh plan | ./run.sh apply | etc.
set -euo pipefail

# Parent subscription the default azurerm provider authenticates against
# (to create the child subscription). Child-sub resources use the aliased
# provider and do not read this.
export ARM_SUBSCRIPTION_ID="${ARM_SUBSCRIPTION_ID:?Set ARM_SUBSCRIPTION_ID to your parent subscription ID}"

# State backend — pre-existing, outside this repo's Terraform.
# Export TF_BACKEND_RESOURCE_GROUP, TF_BACKEND_STORAGE_ACCOUNT before running.
BACKEND_RESOURCE_GROUP="${TF_BACKEND_RESOURCE_GROUP:?Set TF_BACKEND_RESOURCE_GROUP}"
BACKEND_STORAGE_ACCOUNT="${TF_BACKEND_STORAGE_ACCOUNT:?Set TF_BACKEND_STORAGE_ACCOUNT}"
BACKEND_CONTAINER_NAME="${TF_BACKEND_CONTAINER:-tfstate}"
# State key matches the stack directory name so renaming one forces renaming
# the other — prevents silent divergence between code and state location.
BACKEND_KEY="guardianlink-dev"

terraform init \
  -backend-config="resource_group_name=${BACKEND_RESOURCE_GROUP}" \
  -backend-config="storage_account_name=${BACKEND_STORAGE_ACCOUNT}" \
  -backend-config="container_name=${BACKEND_CONTAINER_NAME}" \
  -backend-config="key=${BACKEND_KEY}"

# Refresh Azure CLI's cached subscription list so the aliased
# azurerm.workload provider can authenticate against the child sub.
# Without this, the first apply that creates the subscription leaves
# the CLI cache stale and the next TF step errors with
# "subscription ID ... is not known by Azure CLI".
az account list --refresh >/dev/null

COMMAND="${1:-}"

if [ "$COMMAND" = "apply" ]; then
  shift  # remaining args (e.g. -auto-approve) forwarded to both applies

  # Stage 1: create Grafana Azure resource and Admin role assignment so we can
  # obtain the endpoint URL and a valid API token for Stage 2.
  terraform apply \
    -target=azurerm_dashboard_grafana.main \
    -target=azurerm_role_assignment.grafana_admin \
    "$@"

  # Azure role-assignment propagation takes a few seconds.
  echo "Waiting 30s for role assignment propagation..."
  sleep 30

  # Obtain the Grafana endpoint and an Azure AD bearer token.
  # Azure Managed Grafana accepts AAD tokens at its HTTP API — no Grafana
  # service account key needed. Token TTL is 1 hour, ample for any apply.
  export GRAFANA_URL
  GRAFANA_URL=$(terraform output -raw grafana_endpoint)
  export GRAFANA_AUTH
  GRAFANA_AUTH=$(az account get-access-token \
    --resource ce34e7e5-485f-4d76-964f-b3d2b16d1e4f \
    --query accessToken -o tsv)

  # Stage 2: full apply — Grafana provider now has URL + auth via env vars.
  terraform apply "$@"

else
  terraform "$@"
fi
```

    addSpnToEnvironment: true

        -backend-config="subscription_id=$(TF_BACKEND_SUBSCRIPTION_ID)" \
        -backend-config="resource_group_name=$(TF_BACKEND_RESOURCE_GROUP)" \
        -backend-config="storage_account_name=$(TF_BACKEND_STORAGE_ACCOUNT)" \
        -backend-config="container_name=$(TF_BACKEND_CONTAINER)" \
        -backend-config="key=$(TF_BACKEND_STATE_KEY)" \
        -input=false -reconfigure
      export GRAFANA_URL
      GRAFANA_URL=$(terraform output -raw grafana_endpoint)
      export GRAFANA_AUTH

        --resource ce34e7e5-485f-4d76-964f-b3d2b16d1e4f \

      sleep 30

        -target=grafana_data_source.azure_monitor \
        -target=grafana_dashboard.crash_pipeline \
        -input=false

    TF_VAR_budget_contact_email: $(TF_VAR_budget_contact_email)

## After Task 9: Build the crash-pipeline dashboard

This is the interactive learning part — not automated by Terraform.

1. Open Grafana → Dashboards → crash-pipeline
2. Add panels using the Azure Monitor data source. KQL queries against `log-guardianlink-dev-weu`:

**Panel: crash_suspect events over time (timeseries)**
```kusto
customEvents
| where name == "crash_suspect"
| summarize count() by bin(timestamp, 1m)
| render timechart
```

**Panel: crash_confirmed vs crash_below_threshold (stacked bar)**
```kusto
customEvents
| where name in ("crash_confirmed_published", "crash_below_threshold")
| summarize count() by name, bin(timestamp, 5m)
| render barchart
```

**Panel: classifier confidence distribution (histogram)**
```kusto
customEvents
| where name == "crash_below_threshold"
| extend confidence = todouble(customDimensions["confidence"])
| summarize count() by bin(confidence, 0.01)
```

**Panel: notifier success/failure (stat)**
```kusto
customEvents
| where name in ("notification_sent", "notification_failed")
| summarize count() by name
```

3. Save dashboard → Dashboard settings → JSON model → copy
4. Paste into `dashboards/grafana/crash-pipeline.json` (replace placeholder). **Remove the `"id"` field** from the exported JSON — Grafana includes `"id": <integer>` in exports, which conflicts on re-import into a fresh instance. Delete that key; Grafana re-assigns it on next apply.
5. `./run.sh apply` — Terraform provisions the saved dashboard
6. Commit: `git add dashboards/grafana/crash-pipeline.json && git commit -m "feat(dashboards): crash pipeline Grafana dashboard"`
